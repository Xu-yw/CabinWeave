# 前端

代码：
- `frontend/src/App.vue`：顶栏与页面切换。
- `frontend/src/views/`：`CockpitView.vue`（座舱）、`EvalView.vue`（评测）、`SystemView.vue`（系统）。
- `frontend/src/components/`：`VehiclePanel.vue`、`CarTopView.vue`、`ChatPanel.vue`、`TracePanel.vue`、`BarChart.vue`、`AppIcon.vue`、`BrandMark.vue`。
- `frontend/src/lib/`：`api.js`（接口封装）、`session.js`（座舱会话状态）、`labels.js`（中文名与取值格式）。
- `frontend/src/styles.css`：设计变量与公共样式。
- 配套的后端接口：`backend/api/main.py` 的 `GET /profile`、`GET /eval/report`。

## 1. 定位

横屏深色的车机风格界面，演示和调试放在一起：左边看车辆怎么变，中间对话，右边看这句话在系统里经过了哪些步骤。回复只用文字。

技术栈：Vue 3 + Vite，没有其他运行时依赖；图表和车身俯视图都是手写 SVG 或 HTML。Docker 里由 Nginx 提供静态页面，并把 `/api/python/` 代理到后端。

## 2. 视觉

夜间仪表台配色，三种颜色各有固定含义：

| 颜色 | 含义 |
|---|---|
| 冰蓝 `#7cc6e6` | 助手回复、完整链路 |
| 琥珀 `#f2a83b` | 本轮变化的状态、快速通道 |
| 红 `#ef5b5b` | 被安全规则拦截、低胎压、故障灯 |

- 底色为深蓝灰 `#0f1722`，面板 `#151f2c`，面板内的分组 `#1c2836`。
- 文字用系统中文字体（HarmonyOS Sans、苹方、微软雅黑）。数字用 Bahnschrift / DIN 这类仪表风格字体并等宽显示，不加载网络字体。
- 车身俯视图是页面上最显眼的元素，其余部分保持克制。只有两处动效：双闪闪烁、后备箱掀起，系统开启"减少动态效果"时关闭。

## 3. 页面

**顶栏**：品牌、页面切换、场景下拉框（6 个预设）、重置车辆、用户 ID、新对话。场景下拉框显示本页最近一次套用的场景，刷新后显示"选择场景"，因为前端不知道车辆当前对应哪个预设。

**座舱**（三栏）

| 栏 | 内容 |
|---|---|
| 车辆 | 车速、档位、驾驶模式；电量条和续航（低于 20% 变琥珀色）；车身俯视图；空调、风量、除雾、主副驾座椅加热、音量；媒体、导航；四轮胎压（低于 200 kPa 标红）；故障灯 |
| 对话 | 用户和助手的消息；助手回复下标出通道（快速通道带规则号，完整链路带参与的 Agent）和编排器耗时，被拦截的操作标红；点一条回复，右栏切换到它的链路。输入框上方是 6 组快捷指令：快速指令、多意图、安全拦截、用车问答、导航、偏好记忆，其中安全拦截和偏好记忆带操作提示 |
| 链路追踪 | 按请求链路的先后编号：① 通道（是否命中快速通道、哪条规则）；② 意图识别（主意图、置信度、决策层，以及关键词层和 LLM 层各自的判断、命中词、紧急短语）；③ 子任务与派发（子任务、并行或串行、派发到的角色，快速通道时省略）；④ 工具调用（工具、Agent、参数、耗时，被拦截的标红）；⑤ 车辆状态（被拦截的规则和原因，字段的旧值 → 新值）。右栏可以收起，收起状态记在浏览器里 |

车身俯视图（`CarTopView.vue`，车头朝上）随状态变化：
- 四个侧窗和天窗按开度露出夜色，旁边标出百分比。
- 后备箱打开时尾门向后掀起。
- 车锁为绿色表示已锁，琥珀色表示未锁。
- 双闪开启时四角灯闪烁；氛围灯开启时车内亮起一圈紫光。
- 本轮变化的部件描琥珀色，3 秒后恢复。面板里的其他字段同样按 `state_changes` 高亮。

**评测**：读取 `GET /eval/report` 的正式报告。
- 开头一句说明样本、模型、遍数、生成时间和代码版本，下面 4 条结论各带一个数字。
- E1、E2 两张表，各配一张横向条形图：E1 比较三组的主意图准确率；E2 比较端到端延迟，因为两者差了近 4 个数量级，用对数刻度并在图下注明。
- 错例按组列出，主意图错例显示"应为 / 判成"和判错的遍数，多意图错例显示应拆和实际拆出的意图及执行方式。
- 没有报告时（404），提示生成和复制报告的命令。

**系统**
- 快慢通道：请求数、快速通道占比、开关状态、各规则命中次数。
- 驾驶员偏好：当前用户的偏好、家和公司地址、备注；没有时提示怎么让系统记住。
- 用车手册检索：片段数和检索测试，结果显示标题、相关度和前 120 字。
- Skills：名称、适用角色、说明，可以重新加载。

## 4. 数据流

- `lib/api.js`：后端地址取运行时配置 `window.__CABINWEAVE_CONFIG__.pythonApiUrl`，默认 `/api/python`。接口出错时抛出 FastAPI `detail` 里的中文原因；连不上时提示"连不上后端服务"。
- `lib/session.js`：座舱状态用一个 `reactive` 对象在页面之间共享，切到评测页再回来，对话还在。
  - 发送：先追加用户消息，调用 `/chat`；收到后追加助手消息，用 `vehicle_state` 刷新车辆面板，按 `state_changes` 高亮；再异步调用 `/trace/tool/{request_id}` 取工具调用明细，挂到这条消息上。
  - 切场景、重置车辆：调用 `/vehicle/scenario`、`/vehicle/reset`，在对话里插入一条居中的提示。
  - 用户 ID、会话 ID 存在 localStorage，读写失败时只在内存里保留；换用户时清空对话并重新读取车辆。
- 页面宽度小于 1100px 时三栏改为上下排列，宽度小于 760px 时顶栏换行，手机宽度下没有横向滚动。

## 5. 配套的后端接口

| 接口 | 返回 |
|---|---|
| `GET /profile?user_id=` | `{user_id, profile}`，profile 为规整后的 `{preferences, places, notes}`，没有时为空对象 |
| `GET /eval/report` | `backend/evaluation/报告/report.json` 的内容，不存在时 404。正式报告随镜像打包，`.dockerignore` 只排除每次运行的 `结果/` |

## 6. 已知局限

- 对话气泡只存在页面内存里，刷新后不恢复；后端的对话记录仍在，下一轮会接着用。
- 车辆状态在用户发指令或切场景时刷新，不轮询；用 `POST /vehicle/state` 从外部改状态时，需要刷新页面才能看到。
- 链路追踪的工具调用只有参数、成败和耗时，不含工具返回的完整结果。
- 系统页的手册检索会显示手册原文片段，只适合本地查看，截图对外展示前要注意版权。
