# 意图识别

代码：`backend/core/intent_recognizer.py`（识别器）、`backend/core/text_normalize.py`（文本归一化）、`backend/tests/test_intent_rules.py`（单元测试）。

## 1. 定位与接口

识别器位于快速通道之后、Agent 路由之前。快速通道没命中的输入都会进入这里。

```python
result = await recognizer.recognize(message, history)   # history: [{"role": ..., "content": ...}]
```

返回 `IntentResult`：主意图、置信度、子任务、执行方式，以及两层各自的判断（`sources`）。

## 2. 意图体系

14 个意图，每个意图直接映射到一个 Agent。

| Agent | 意图 |
|---|---|
| 车控 | climate_control 空调温控、body_control 车身控制、drive_setting 驾驶设置 |
| 导航 | navigation 导航路线、poi_search 周边搜索 |
| 用车顾问 | vehicle_status 车况查询、fault_diagnosis 故障诊断、manual_qa 用车问答 |
| 座舱助手 | media_control 影音控制、phone_call 电话消息、chitchat 闲聊问候、other 无法识别 |
| 安全节点 | emergency_sos 紧急求助、roadside_assist 道路救援 |

安全节点负责的 2 个意图是安全类意图（`SAFETY_INTENTS`），选主意图时优先。转人工、投诉不提供，归 other，由座舱助手说明暂不支持。

**标注约定**：易混淆的类别按下表区分。LLM prompt 里的边界规则按这张表写，评测样本也按它标注。

| 易混淆 | 约定 |
|---|---|
| climate_control / body_control | 座椅、方向盘加热通风算 climate（热舒适）；座椅位置、按摩算 body |
| vehicle_status / fault_diagnosis | 问读数或状态（"胎压多少"）算 status；出现报警、指示灯、异常现象（"胎压报警了"）算 diagnosis |
| fault_diagnosis / manual_qa | 针对本车当前现象算 diagnosis；一般知识或功能用法算 manual_qa |
| drive_setting / manual_qa | 要求切换或开关算 drive_setting；问功能是什么、怎么用算 manual_qa |
| navigation / poi_search | 有明确目的地或路线操作算 navigation；按类别找地点算 poi_search（即使说"导航去最近的充电站"） |
| roadside_assist / emergency_sos | 车辆无法行驶但无人身风险算 roadside；有人身安全风险（事故、起火、受伤、疾病）算 sos |
| other / roadside_assist | 要人工、客服、投诉算 other（不提供转人工）；要救援、拖车算 roadside |
| chitchat / other | 有明确社交或信息诉求算 chitchat；判断不出诉求算 other |
| 一句多指令 | 主意图：安全类优先，否则取第一个诉求；其余诉求另标为子意图 |

## 3. 识别流程

采用"关键词 + LLM"分层识别：

```
recognize(message, history)
 ├─ LRU 缓存命中 → 直接返回
 ├─ 关键词层（同步，毫秒级）
 │    ├─ 紧急短语命中 → 判为 emergency_sos，不调 LLM
 │    ├─ 意图词表计数 → 候选意图
 │    └─ 分句检测多意图 → 候选子任务
 ├─ LLM 层（文本 JSON 输出，超时 5 秒）→ 主意图 + 子任务 + 执行方式
 └─ 决策 → IntentResult
```

## 4. 关键词层

匹配前统一做全角转半角、去空格、转小写。

**紧急短语（34 条）**

- 只收高精度短语，如"车着火了""撞车了""有人受伤""喘不上气"。"救命""着急"这类泛化词不收，否则"救命，好热"会被误判。
- 否定和假设保护：短语前 6 个字以内（同一分句）出现"没有、差点、万一、如果"等 12 个词，或紧挨着"没、不、未、别"时，不算命中。例如"差点追尾了""没有人受伤"不会触发。
- 命中后直接返回 emergency_sos，不调用 LLM，紧急情况零等待。

**意图词表（423 个词，覆盖除 other 外的 13 类）**

- 每类收同义词和常见语音识别同音错字，例如"空挑"→空调、"倒航"→导航、"后背箱"→后备箱。
- 不重叠的最长匹配：同一位置只算最长的词，所以"座椅加热"只算 climate_control，不会再算 body_control 的"座椅"。
- 计数：统计每个意图命中的词数，取命中最多的意图。
- 平局按优先级取：安全类 > 故障 > 电话 > 地点 > 导航 > 问答 > 车况 > 车控 > 影音 > 闲聊。例如"打电话给4S店"取电话，"导航去充电站"取地点，"空调坏了"取故障。

**分句检测多意图**

- 按标点和连接词（然后、再、顺便、并且、同时、还有、另外、接着）切分，并用前瞻排除"还有多久""再见"。
- 每个片段单独计数。没命中的片段和问候、闲聊片段并入相邻片段，避免"你好，打开空调"被拆成两个诉求。
- 片段落在 2 个以上意图时标记多意图，同意图片段合并成一个候选子任务，最多 4 个。车窗和空调这类同属车控的不同意图也会拆开，由路由合并派给车控。主意图按"安全类优先，否则第一个诉求"选取。
- 这份候选只在 LLM 不可用时使用。

## 5. LLM 层

**prompt**

- system prompt 是静态内容（约 3100 字），便于服务端做 prompt 缓存。包含：14 个意图的定义、9 条边界规则、多诉求规则、28 条单诉求示例（每类 2 条）、3 条多诉求示例。
- 明确告诉模型：输入来自语音识别，可能有口语、省略和同音错字。
- user 消息放最近 3 条历史和当前文本，用于理解"再低一点"这类省略。
- 示例不得复用为评测样本，代码注释里已写明。

**请求参数**

关闭思考模式（`extra_body=THINKING_DISABLED`），`max_tokens` 为 512，`temperature` 为 0.1。输出只是一个短 JSON，不需要思考过程，关闭后延迟更低，也不容易超时。

**输出格式**

模型只输出一个 JSON 对象：

| 字段 | 约束 |
|---|---|
| intent | 14 个意图之一，必填 |
| reasoning | 一句话判断依据，必填 |
| sub_tasks | 数组，最多 4 项，每项包含 intent 和 text（原话片段） |
| execution | parallel 或 sequential |

解析时忽略思考块，从文本里截取第一个 `{` 到最后一个 `}` 之间的内容。

**超时与失败**

用 `asyncio.wait_for` 控制超时（默认 5 秒）。超时、调用异常、解析失败都算 LLM 失败，交给关键词兜底。

**输出校验**

- 主意图不合法 → other。
- 子任务意图不合法或文本为空 → 丢弃；剩不到 2 个 → 视为单诉求；最多保留 4 个。
- 只有存在子任务时才可能是 sequential。
- 主意图校正：子任务里有安全类时取第一个安全类；主意图本身是安全类时保持不变；主意图不在子任务里时取第一个子任务。

## 6. 决策规则

按顺序判断：

| 情况 | 最终意图 | 置信度 | decided_by |
|---|---|---|---|
| 命中紧急短语 | emergency_sos | high | emergency_rule |
| LLM 成功，与关键词候选一致 | LLM 结果 | high | llm |
| LLM 成功，与关键词候选不一致 | LLM 结果 | medium | llm |
| LLM 判为 other | other | low | llm |
| LLM 失败或超时，关键词有候选 | 关键词候选（多意图时带子任务） | low | keyword_fallback |
| 都没有结果，或输入为空 | other | none | none |

- 置信度只有等级，按两层是否一致给出，不用 LLM 自报的数字。
- LLM 失败或超时的结果不进缓存，下次同一句话会重新调用 LLM。

## 7. 输出结构

**IntentResult**

| 字段 | 说明 |
|---|---|
| intent | 主意图 |
| confidence_level | 置信度等级（high / medium / low / none） |
| reasoning | 判断依据 |
| latency_ms | 识别耗时 |
| sources | 两层各自的判断，见下表 |
| sub_tasks | 子任务列表，为空或 2–4 个 |
| execution | parallel / sequential |

**sources**：记录每一层做了什么，供前端展示和评测统计各层贡献。

| 字段 | 说明 |
|---|---|
| keyword_intent、keyword_counts、keyword_hits | 关键词层的候选意图、各意图命中数和命中词 |
| keyword_sub_tasks、multi_intent_keyword | 关键词层的分句结果 |
| emergency_phrase | 命中的紧急短语 |
| llm_intent、llm_status | LLM 的判断和状态（ok / failed / timeout / skipped） |
| llm_error | 失败时的异常类型（只给类型，完整信息只写服务端日志，避免泄露服务地址） |
| decided_by | 最终由哪一层决定 |

API 响应里对应字段为 `intent_sources`。

## 8. 配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| CABINWEAVE_INTENT_MODEL | 空（沿用全局模型） | 识别器单独用的模型，可配更快的小模型 |
| CABINWEAVE_INTENT_TIMEOUT_S | 5.0 | LLM 超时秒数 |
| CABINWEAVE_INTENT_CACHE_SIZE | 1000 | LRU 缓存容量，0 表示不缓存 |

非法值会记录 warning 并使用默认值，不影响启动。

构造参数 `use_keywords`、`use_llm` 默认都为 True，可以关掉其中一层（不能都关）：
- `use_llm=False`：只用关键词层，结果和 LLM 不可用时一样，`llm_status` 为 skipped。
- `use_keywords=False`：只用 LLM 层，没有紧急直达和关键词兜底，LLM 失败时判为 other。

线上不用这两个参数，评测的分层消融用它们构造对照组（见 [意图评测](08-意图评测.md)）。

## 9. 已知局限

- LLM 不可用时，"万一着火了怎么办"这类假设问句不会走紧急直达，但词表里有"着火"，关键词兜底仍会判成 emergency_sos。
- 一句多诉求时，置信度只比较两层的主意图，容易偏低（medium）。
- "预约充电"目前放在 manual_qa 词表里，14 类中没有充电控制意图。
