# 模拟车辆与安全规则

代码：`backend/vehicle/state.py`（车辆状态与存储）、`backend/vehicle/safety.py`（安全规则）、`backend/vehicle/service.py`（车辆服务接口）、`backend/vehicle/mock_services.py`（模拟外部服务）、`backend/agents/agent_orchestrator.py`（接入编排器）、`backend/tests/test_vehicle_state.py`、`backend/tests/test_vehicle_safety.py`（单元测试）。

## 1. 定位

这一层给系统补上"一辆车"：一份可读可写的车辆状态、一套执行前的安全规则，以及几个返回固定数据的模拟外部服务。

```
Agent 工具 / 快速通道 / 安全节点
        │  命令 {"action", "args"}
        ▼
VehicleService.execute ──► SafetyPolicy.check（放行 / 调整 / 拒绝）
        │
        ▼
VehicleStateStore（按用户隔离的车辆状态）──► 快照 ──► 角色输入包
```

这一层是车辆服务接口的抽象边界：现在接进程内的模拟存储，将来接真实车控服务时只替换这一层，工具和 Agent 不用改。

## 2. 车辆状态

状态用普通 dict 表示，便于序列化和按角色裁剪。只保留工具会写、安全规则会查、用车顾问会问、场景预设会设的字段：

| 分组 | 字段 | 默认值（停车） |
|---|---|---|
| 行驶 | speed_kmh、gear（P/R/N/D）、drive_mode（eco/comfort/sport） | 0、P、comfort |
| 能源 | battery_pct、range_km | 80、400 |
| 空调 climate | on、temp（16–32℃）、fan_level（1–7）、defrost（前挡除雾） | 关、24、3、关 |
| 座椅 seats | seat_heat（driver、passenger，0–3） | 0、0 |
| 车身 body | windows（fl、fr、rl、rr，0–100%）、sunroof（0–100%）、doors_locked、trunk_open | 全关、0、上锁、关 |
| 灯光 lights | ambient、hazard | 关、关 |
| 车况 | tire_pressure_kpa（四轮）、warning_lights、next_service_km、outside_temp_c | 250×4、无、5000、20 |
| 位置/导航 | location（city、address）、navigation（active、destination、eta_min） | 上海徐汇（示例）、未导航 |
| 媒体 media | playing、title、volume（0–30） | 未播放、空、12 |

**场景预设**（在默认状态上覆盖）：

| 场景 | 覆盖内容 |
|---|---|
| parked | 停车（即默认状态） |
| city_driving | 40 km/h，D 档 |
| highway | 110 km/h，D 档 |
| low_battery | 电量 12%，续航 60 km |
| tpms_warning | 左前胎压 180 kPa，故障灯"胎压报警" |
| winter | 室外 -5℃，续航 300 km |

**存储 `VehicleStateStore`**：

- 进程内 dict，按 user_id 隔离，一个用户一辆车，新对话不重置；user_id 为空时报错。
- `get` 返回内部状态（只给车辆服务修改），不存在时按默认场景创建；`snapshot` 返回深拷贝。
- `reset(user_id, scenario)` 恢复默认状态或套用场景；`update(user_id, patch)` 按嵌套 dict 局部更新，用来模拟车速、电量、故障灯。update 只允许已存在的键，类型要和原值一致，档位、驾驶模式、电量等有取值校验，一处出错整次不生效。
- 带一把可重入锁，车辆服务的"读-改-写"在锁内完成，中间没有 await。
- 多实例部署时可以换成 Redis 实现，接口不变。

## 3. 安全规则

所有写操作在执行前统一调用 `SafetyPolicy.check(state, command)`，返回 `SafetyDecision(allowed, adjusted_args, notice, rule_id, rule_ids)`：

| 规则 | 条件 | 处理 | 播报示例 |
|---|---|---|---|
| S01 行驶中禁开尾门 | 打开尾门，且车速 > 0 或不在 P 档 | 拒绝 | 车辆行驶中不能打开后备箱，请停车后再试。 |
| S02 行驶中禁解锁车门 | 解锁，且车速 > 0 | 拒绝 | 车辆行驶中不能解锁车门，请停车后再试。 |
| S03 高速限制开度 | 车速 > 100，车窗或天窗开度 > 30% | 调整为 30% | 高速行驶中车窗最多只能开到30%，已为你开到30%。 |
| S04 温度范围 | 不在 16–32℃ | 裁剪到边界 | 温度最高只能调到32度，已为你调到32度。 |
| S05 档位、音量范围 | 风量 1–7、座椅加热 0–3、音量 0–30 之外 | 裁剪到边界 | 风量最高只能调到7档，已为你调到7档。 |
| S06 主动安全功能 | 语音关闭 ESP、自动紧急制动等 | 一律拒绝 | 为了行车安全，车身稳定系统不能语音关闭，如需调整请到车辆设置中手动操作。 |
| S07 低电量提醒 | 电量 < 15% 时开启/调高座椅加热或调高风量 | 放行并提醒 | 当前电量只剩12%，座椅加热会增加耗电，建议尽快充电。 |

- **相对调节先换算**："调高两度""风大一点"按当前状态换算成目标值，再过范围规则，所以裁剪基于换算后的值。adjusted_args 里只有绝对值。
- **多条规则同时触发**（如 S05 裁剪加 S07 提醒）时，notice 按规则顺序拼接；`rule_id` 是第一条触发的规则，`rule_ids` 列出全部。
- **裁剪后值没变**时说"温度已经是最高的32度了。"，不说"已为你调到"。
- notice 和拒绝原因都是可以直接播报的中文短句。

## 4. 车辆服务接口

`VehicleService(store, policy)` 对外只暴露同步方法 `execute(user_id, command)` 和 `snapshot(user_id)`。命令结构是 `{"action": "...", "args": {...}}`，可用 `make_command(action, **args)` 构造。

**命令词表**（"二选一"表示两个参数必须给且只能给一个）：

| action | 参数 | 说明 |
|---|---|---|
| set_climate_power | on | 空调开关 |
| set_temperature | temp 或 delta，二选一 | 温度；同时打开空调 |
| set_fan | level 或 delta，二选一 | 风量；同时打开空调 |
| set_defrost | on | 前挡除雾 |
| set_seat_heat | zone（driver/passenger/all，默认 driver）；level 或 delta，二选一 | 座椅加热 |
| set_window | zone（fl/fr/rl/rr/all，默认 fl）；open_percent（0–100） | 车窗开度 |
| set_sunroof | open_percent（0–100） | 天窗开度 |
| set_trunk | open | 尾门 |
| set_door_lock | locked | 上锁 / 解锁 |
| set_ambient_light | on | 氛围灯 |
| set_hazard | on | 双闪 |
| set_drive_mode | mode（eco/comfort/sport） | 驾驶模式 |
| set_volume | level 或 delta，二选一 | 音量 |
| media_control | op（play/pause/next/previous）；title（可选） | 播放状态 |
| set_navigation | destination；eta_min（可选） | 设置导航 |
| cancel_navigation | — | 取消导航 |
| set_active_safety | feature（如 esp/aeb，也接受中文名）；on | 主动安全功能；关闭一律被 S06 拒绝，开启不改状态 |

**执行流程**：校验命令和参数 → 取状态 → 安全规则 → 被拒绝时状态不变 → 放行时按调整后的参数写入 → 返回变化。

**返回值**：

| 情况 | 返回 |
|---|---|
| 放行 | `{"success": true, "changes": [{"field": "climate.temp", "old": 24, "new": 22}], "notice": "...", "rule_ids": [...]}`，值没变的字段不进 changes |
| 拒绝 | `{"success": false, "blocked": true, "rule_id": "S01", "reason": "..."}` |
| 不支持 | `{"success": false, "unsupported": true, "reason": "暂不支持这个功能"}` |
| 参数错误 | `{"success": false, "error": "..."}` |

不支持、参数错误、被拒绝时都不改状态。雨刮、后视镜、座椅通风、方向盘加热、能量回收等状态里没有的功能，由工具返回不支持（见 [工具](04-工具.md) 第 3 节）。

## 5. 模拟服务

全部是确定性数据，不访问网络，演示和评测可复现：

| 服务 | 函数 | 内容 |
|---|---|---|
| 地图 | `search_poi`、`plan_route` | 当前位置固定在上海徐汇（示例）；15 个虚构 POI，覆盖充电站、停车场、服务区、维修点、餐厅，充电站带空闲桩数、总桩数和功率；可按类别或关键词检索，按距离、空闲桩、功率排序，可只要有空闲桩的充电站。6 个常用目的地（机场、火车站、商场等）可查路线距离和时长。名称都带"（示例）" |
| 天气 | `get_weather` | 按城市名（指定了其他日期时连同日期）哈希出固定的天气和温度区间 |
| 媒体 | `search_media` | 不编造真实曲目，只返回"{关键词}相关内容（示例曲库）" |
| 联系人 | `find_contact` | 5 个虚构联系人，号码打码，可按名字或称呼（如"老婆""妈妈"）查找 |

- "家""公司"不在地图里，由驾驶员偏好提供（第 5、7 节）。
- 目的地匹配不到、或"机场""火车站"这类有多个候选时，返回需要确认，并列出候选。
- 联系人完全匹配优先，其次部分匹配；匹配到多个返回需要确认，匹配不到返回 not_found。

## 6. 与编排器的衔接

- **车辆服务**：编排器持有一个 `VehicleService`（`self.vehicle`），也可以由外部传入，便于 API 层和测试共享同一个实例。
- **车辆**：一个用户一辆车，编排器、工具和快速通道都按 `req.user_id` 读写车辆状态。
- **快照**：调用方没传 vehicle_state 时从车辆服务取。并行时各 Agent 用同一时刻的快照；串行时每个 Agent 派发前重新取，看到的是上一个 Agent 改过之后的状态。
- **安全节点的车辆操作**：经车辆服务执行，同样过安全规则，播报按实际结果说：

| 意图 | 车辆操作 | 播报 |
|---|---|---|
| emergency_sos | 打开双闪；车速为 0 时解锁车门（行驶中被 S02 拒绝） | 停车时"已为你打开双闪并解锁车门。"；行驶中"已为你打开双闪，请尽快在安全的地方停车。" |
| roadside_assist | 打开双闪 | "已为你打开双闪，请把车停在安全位置，……" |

- **状态变化汇总**：工具返回带 `changes` 时并入 `state_changes`，返回 `blocked: true` 时把 `{tool_name, rule_id, reason}` 并入 `blocked_actions`；安全节点的车辆操作同样汇总。Agent 失败时保留它失败前已产生的变化。两项都写进 OrchestratorResult 和请求级 trace。
