# 工具

代码：`backend/agents/tools.py`（全部 Agent 工具）、`backend/vehicle/warning_lights.py`（故障灯表）、`backend/agents/agent_orchestrator.py`（注册与工具循环）、`backend/tests/test_vehicle_tools.py`（单元测试）。

## 1. 定位

工具是 Agent 真正"做事"的地方：模型决定调哪个工具、传什么参数，工具负责执行并把结果交回模型。4 个 LLM 角色共 15 个工具：

| 角色 | 工具 |
|---|---|
| 车控 | set_climate、set_body、set_lighting、set_drive_mode |
| 导航 | search_poi、plan_route、get_route_status |
| 用车顾问 | lookup_warning、estimate_range、search_knowledge_base |
| 座舱助手 | control_media、set_volume、make_call、get_weather、suggest_required_fields |

- 编排器构造时用 `build_agent_tools(self.vehicle)` 注册全部角色工具，RAG 由 `build_rag_tools` 注册；各角色只能看到自己 tool_scope 内的工具（见 [Agent 角色与路由](02-Agent角色与路由.md) 第 3 节）。
- handler 签名统一为 `(req, args)`，需要车辆服务的工具用 `functools.partial` 绑定 VehicleService。快速通道可以直接调用同一个函数。
- 一个用户一辆车，车辆状态按 `req.user_id` 读写。

## 2. 通用约定

- **写操作一律经车辆服务**：所有改车辆状态的操作都调用 `VehicleService.execute`，同样过安全规则 S01–S07（见 [模拟车辆](03-模拟车辆.md)），工具本身不直接改状态。
- **一次调用多条命令**：例如 set_climate 同时设温度和座椅加热，会依次执行多条命令，再合并成一个返回值。
- **参数校验**：编排器只校验必填、类型和多余字段，枚举值和互斥参数由工具自己校验。不合法时返回 `{"success": false, "error": "..."}`，不抛异常。枚举值同时接受标准值和常见中文叫法，比如 `part` 填"后备箱"也能识别成 trunk。
- **返回值保持紧凑**：只返回结论和必要字段，不带整份车辆状态。

**写操作的合并返回值**：

| 字段 | 说明 |
|---|---|
| success | 全部命令都成功才为 true |
| changes | 全部状态变化 `[{"field", "old", "new"}]`，编排器据此汇总 state_changes |
| notice | 调整说明和提醒，按顺序拼接，可直接播报 |
| rule_ids | 触发的全部安全规则（含被拒绝的） |
| blocked、rule_id、reason | 有命令被拒绝时出现：rule_id 是第一条被拒的规则，reason 是全部拒绝原因；编排器据此汇总 blocked_actions |
| unsupported、unsupported_features | 有不支持的功能时出现，列出功能名 |
| error | 参数错误说明 |

## 3. 不支持的功能

车辆状态里没有的功能，也在工具参数里给出可选值，调用后返回 `unsupported: true` 和"暂不支持这个功能"，状态不变。这样模型总有工具可调，会如实播报"暂不支持"，不会假装执行成功。

| 工具 | 不支持的可选值 |
|---|---|
| set_body | part：wiper（雨刮）、mirror（后视镜）、sunshade（遮阳帘）、seat（座椅位置）、other |
| set_lighting | type：headlight（大灯）、reading（阅读灯）、fog（雾灯）、other |
| set_climate | comfort_feature：seat_ventilation（座椅通风）、steering_wheel_heat（方向盘加热）、seat_massage（座椅按摩）；seat_heat_zone：rear（后排座椅加热） |
| set_drive_mode | regen_level（能量回收）、steering_mode（转向手感） |

和支持的项一起传时，支持的项照常执行，success 为 false，结果里同时有 changes 和 unsupported_features。

## 4. 车控工具

| 工具 | 参数 | 对应车辆命令 |
|---|---|---|
| set_climate | power；temperature 或 temperature_delta；fan_level 或 fan_delta；defrost；seat_heat_zone（driver/passenger/all）＋ seat_heat_level 或 seat_heat_delta；comfort_feature | set_climate_power、set_temperature、set_fan、set_defrost、set_seat_heat |
| set_body | part（window/sunroof/trunk/door_lock）、action（open/close/lock/unlock）、zone、open_percent | set_window、set_sunroof、set_trunk、set_door_lock |
| set_lighting | type（ambient/hazard）、action（on/off） | set_ambient_light、set_hazard |
| set_drive_mode | mode（eco/comfort/sport）；assist_feature ＋ assist_on | set_drive_mode、set_active_safety |

- **set_climate**：命令按"打开空调 → 温度 → 风量 → 除雾 → 座椅加热 → 关闭空调"的顺序执行；关闭空调时不能同时调温度或风量。座椅加热不说位置时默认主驾。
- **set_body**：
  - 车窗不说位置时默认主驾。zone 接受 fl/fr/rl/rr/all，也接受 driver、passenger、front、rear、left、right 和中文说法，一个说法对应多扇窗时展开成多条命令。
  - 不给 open_percent 时，打开为 100、关闭为 0。
- **set_drive_mode**：驾驶辅助功能的中文名会换算成 esp/aeb/fcw/lka/bsd。关闭一律被 S06 拒绝；开启时成功但没有 changes，因为状态里不记录这些功能。

## 5. 导航工具

| 工具 | 参数 | 返回要点 |
|---|---|---|
| search_poi | category、keyword、sort_by（distance/available/power）、require_available | 地点列表：名称、类别、地址、距离、时长，充电站另带空闲桩、总桩数、功率；都不传时返回最近的 5 个 |
| plan_route | destination、preference（fastest/avoid_highway/avoid_toll）、waypoints（最多 3 个） | 成功时返回距离、时长，并经车辆服务写入导航状态；需要确认时返回候选、不写状态；缺地址时返回 need_info |
| get_route_status | — | 是否在导航、目的地、剩余时间、模拟路况（畅通/缓行/拥堵） |

- **家和公司**："家""回家""公司""单位"等说法从驾驶员偏好 `req.profile["places"]` 取地址，偏好里没有时返回需要用户提供。导航状态和返回值里只写"家""公司"，不带具体住址。
- **路线偏好**（模拟）：避开高速，距离 ×1.15、时长 ×1.3；避开收费，距离 ×1.05、时长 ×1.1。
- **路况**：按目的地哈希出固定结果，同一目的地每次相同；不模拟行驶进度。

## 6. 用车顾问工具

**lookup_warning**：查故障灯表，返回颜色、严重度、含义和建议动作。

| 编码 | 故障灯 | 颜色 | 严重度 |
|---|---|---|---|
| W01 | 胎压报警 | 黄 | 注意 |
| W02 | 动力电池故障 | 红 | 严重 |
| W03 | 动力电池过热 | 红 | 紧急 |
| W04 | 电驱系统故障 | 红 | 严重 |
| W05 | 制动系统故障 | 红 | 严重 |
| W06 | 安全气囊故障 | 红 | 严重 |
| W07 | ESP 故障 | 黄 | 注意 |
| W08 | 12V 低压蓄电池电量低 | 黄 | 注意 |
| W09 | 低电量 | 黄 | 注意 |
| W10 | 充电系统故障 | 黄 | 注意 |
| W11 | 功率受限（乌龟灯） | 黄 | 注意 |

- 编码是示例编码，说明都是通用说法，不对应具体品牌。
- 匹配顺序：编码完全一致 → 别名子串取最长匹配（"胎压灯""胎压报警了"都能命中）→ 相似度兜底。
- 不传 signal 时读车辆状态里的 warning_lights，按"紧急 > 严重 > 注意"排序返回；查不到时提示"未收录，建议查看车辆用户手册或联系售后"。

**estimate_range**：传 destination 或 distance_km（二选一），按当前电量、续航和室外温度估算到达后的剩余电量和续航：

1. 需要的续航 = 距离 ×（1 + 低温余量）。0℃ 及以下余量 25%，0–10℃ 余量 10%，10℃ 及以上不留。
2. 剩余续航 = 当前续航 − 需要的续航；剩余电量 = 当前电量 × 剩余续航 ÷ 当前续航，都向下取整，最低为 0。
3. 剩余续航不大于 0 算到不了；到不了或到达后电量低于 15% 时建议途中充电。
4. 结果标注"仅为估算，实际续航受车速、路况、空调和载重影响"。

例如停车场景（80%、400 km、20℃）去浦东机场 52 km，到达约剩 69%、348 km；冬季场景（-5℃、300 km）约剩 62%、235 km。

**search_knowledge_base**：检索车辆用户手册（RAG 链路），检索为空时返回 `found: false` 和"手册里没有找到相关内容"的提示，见 [记忆、知识库与 Skills](06-记忆知识库Skills.md)。

## 7. 座舱助手工具

| 工具 | 参数 | 说明 |
|---|---|---|
| control_media | action（play/pause/next/previous）、query | 经车辆服务写入播放状态；带 query 时标题为"{关键词}相关内容（示例曲库）"，直接播放且没有内容时放"每日推荐（示例曲库）" |
| set_volume | level / delta / mute 三选一 | 静音即调到 0，取消静音且音量为 0 时恢复到 12；S05 负责裁剪 |
| make_call | contact | 模拟拨号，不写车辆状态：唯一匹配时"正在呼叫 某某（打码号码）"，多个匹配返回候选，查不到如实返回 |
| get_weather | city、date | city 默认取车辆状态里的城市 |
| suggest_required_fields | — | 按分到的意图给出要追问的关键信息（目的地、联系人等） |

## 8. 编排器相关改动

- `Request.profile`：驾驶员偏好，`/chat` 从记忆读取后传入（见 [记忆、知识库与 Skills](06-记忆知识库Skills.md)）。
- 工具循环最大轮数为 `MAX_TOOL_ROUNDS = 4`，"搜地点 → 规划路线 → 查路况 → 回复"也有余量。
- 每个 Agent 收到的指令只有分给自己的原话片段（多个片段用"；"连接），完整原话放在角色输入包里作参考，避免回应别的 Agent 负责的部分。
