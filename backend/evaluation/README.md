# CabinWeave 意图识别评测

只评意图识别，覆盖快速通道和意图识别器两层。

| 文件 | 内容 |
|---|---|
| `意图样本.json` | 58 条样本：单意图 48 条（含 10 条易混与对抗样本）、多意图 10 条 |
| `evaluator.py` | 样本校验、E1 / E2 执行、指标计算、Markdown 报告 |
| `运行评测.py` | 命令行入口 |
| `报告/` | 正式一轮的 `report.json` 和 `报告.md`，对外数字以它为准 |
| `结果/` | 每次运行的输出，不提交 |

## 实验

- **E1 分层消融**：只关键词（等同 LLM 不可用）/ 只 LLM（没有紧急直达和关键词兜底）/ 关键词 + LLM，跑全部样本。
- **E2 快速通道开关**：
  - 意图层面：关闭即 E1 的"关键词 + LLM"组，开启时被快速通道命中的样本改用规则对应的意图。
  - 端到端：标 `fast_path` 的样本，每次用一辆套用 parked 场景的新车，分别调用 `orchestrator.run(req, fast_path=True/False)`。

指标：主意图准确率、多意图完全匹配率、快速通道覆盖率与误命中率、延迟 P50 / P95、状态一致率。调用模型的组跑 3 遍取均值，全部串行执行。

## 运行

在仓库根目录执行，读取根目录 `.env` 的模型配置，不需要启动 Docker：

```bash
python backend/evaluation/运行评测.py
```

可选参数：`--repeats N`（默认 3）、`--samples 路径`、`--skip-e2e`（只跑识别器）。全部实验约 500 次模型调用。

## 样本格式

```json
{"id": "S51", "text": "搜一下附近的充电站，然后导航过去", "intent": "poi_search",
 "sub_tasks": [{"intent": "poi_search", "text": "搜一下附近的充电站"}, {"intent": "navigation", "text": "然后导航过去"}],
 "execution": "sequential", "fast_path": false, "note": "导航目的地依赖搜索结果"}
```

- 标注按 [意图识别](../../docs/项目介绍/01-意图识别.md) 第 2 节的标注约定，不复用识别器 prompt 里的示例。
- `fast_path: true` 表示快速通道白名单范围内的单条简单指令（不含疑问、否定、指代和同音错字）。
- 样本定稿后不再修改，报告记录样本文件的 SHA-256。

## 局限

样本为人工编写的合成数据，数量少，单个样本就占约 1.7 个百分点，只看总体指标、不看逐类指标；没有独立的第二人标注。
